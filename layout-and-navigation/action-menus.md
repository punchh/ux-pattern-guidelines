# Action menus

### Usage

Place actions inside of an action menu when:

* **The actions are repeated across rows** of a table or list, and it would look redundant (and over-compete with the page content) to repeat the same buttons over and over again each row
* The actions aren't repeated, but they are **distant secondary and tertiary actions** in the hierarchy of buttons on the page. Often these are low priority utility actions that only get seldom use, and we don't want them competing with more commonly used actions that persist as regular buttons on the page.
  * Admittedly **there is subjectivity** to this case, so expect it to vary heavily by business context

### Access

An action menu is usually accessed from an overflow button that persist on the page.

Common representations are either an ellipsis or 3-dot "kebab" icon by itself, or accompanied by a text label like "More" or "More actions".

Users of our products have been shown in studies to be able to locate action menu actions using the icon alone.

<figure><img src="../.gitbook/assets/image (10).png" alt=""><figcaption><p>A action menu on a table containing actions</p></figcaption></figure>

### Labeling

Like regular buttons that persist on a page, action menu items should:

✅ [Follow a verb](../reading-information/grammar-voice-and-tone.md#voice) + noun pattern (and ideally just the verb alone)

✅ Be [plain-language and specific](../reading-information/grammar-voice-and-tone.md#voice) about what the action is does

✅ Use [Sentence case](../reading-information/grammar-voice-and-tone.md#capitalization)

✅ End in an [ellipsis](../reading-information/grammar-voice-and-tone.md#ellipses) if there are more things to configure or define in a subsequent screen before the action actually gets executed

✅ Have a leading icon to visually reinforce the action
